A graphics processor hides the slowness of memory by running thousands of threads at once. While one group of threads waits for data to arrive from device memory, the scheduler switches to another group that is ready to compute. This only works when there is enough independent work to keep the machine busy. Large matrix multiplications provide plenty of it, which is why training and the first stage of text generation, where the whole prompt is processed together, tend to use the arithmetic units efficiently.

Generating text one token at a time is a different story. For every new token the model must read each of its weights from memory, multiply them by a very small amount of activation data, and throw most of the result away. The amount of arithmetic per byte moved is tiny, so the arithmetic units sit idle and the speed of the memory system sets the pace. Engineers describe this situation as being bound by memory bandwidth rather than by compute.

Several techniques follow from that observation. Storing weights in fewer bits means fewer bytes to move for every token, so a model quantized to eight bits can in principle decode almost twice as fast as the same model in sixteen bits, provided the dequantization is fused into the multiplication instead of running as a separate step. Keeping the attention cache at a fixed size lets the compiler capture the whole decoding step as a single graph and replay it without paying the launch overhead of hundreds of small kernels. Using a fused attention kernel avoids writing the large intermediate score matrix back to memory at all.

Measuring these effects honestly requires care. The device runs asynchronously from the host program, so a timer must wait for the device to finish before it reads the clock. The first few runs are slower because kernels are selected and compiled, so they are discarded. Reporting the median of several runs, along with the spread, protects against a single lucky or unlucky measurement. Finally, any speedup should be accompanied by a quality check, since a faster model that produces worse text has not really been optimized.
